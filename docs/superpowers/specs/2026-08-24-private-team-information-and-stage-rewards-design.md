# 人生大富翁：隊伍資訊保密、私人觀戰與五大關獎勵設計

日期：2026-08-24
狀態：等待使用者最終確認

## 1. 目標與不變條件

本次修改要讓財產資訊直到頒獎揭曉前保持競賽機密，同時保留現場免密碼的大螢幕觀戰，並補齊每隊獨立登入、私人觀眾、五大關實際效果與飛彈自由選隊。

下列規則不變：

- 主持人仍能看見並調整所有隊伍的完整狀態。
- 公開大螢幕仍可免密碼加入並觀看棋盤、角色、動畫和現場進度。
- 最終名次仍以總資產計算，頒獎典禮仍由主持人逐步控制。
- 特殊操作每隊每回合每招限成功使用一次的規則不變。
- 五大關效果不限制每隊或每關觸發次數；解鎖後，每次踩到都生效。

## 2. 採用方案

採用「伺服器依每條 WebSocket 連線投影狀態」的方案。Durable Object 內仍保存唯一、完整的權威遊戲狀態，但傳送前依連線身分建立安全副本。不得只靠 CSS、前端條件判斷或畫面遮罩保密。

不採用每隊獨立遊戲房間，因為會增加棋盤、動畫和頒獎同步失敗的風險；也不採用純前端隱藏，因為瀏覽器開發工具仍能讀到敏感資料。

## 3. 身分與權限模型

### 3.1 主持人

- 使用既有主持人權杖或管理員密碼登入。
- 收到完整狀態、完整日誌、全體收據及所有隊伍登入代碼。
- 可複製或重新產生任一隊的隊輔代碼與觀眾代碼。
- 重新產生代碼時，使用舊代碼的相應在線連線立即被關閉；其他角色連線不受影響。

### 3.2 隊輔

- 先選擇隊伍，再輸入該隊專屬隊輔代碼。
- 只能操作選定隊伍。
- 可收到本隊的現金、諂媚點、背包、增益、收據與其他私人狀態。
- 其他隊伍只保留公開欄位，例如名稱、顏色、位置、基地位置、基地等級、是否售出、是否在線與公開角色狀態。
- 可查看並複製本隊觀眾代碼，但不能看到任何隊輔代碼或其他隊伍觀眾代碼。

### 3.3 指定隊伍觀眾

- 先選擇隊伍，再輸入該隊專屬觀眾代碼。
- 取得與該隊有關的私人顯示資料，但沒有任何遊戲操作權限。
- 可看本隊現金、諂媚點、基地、背包狀態與本隊收據。
- 不顯示任何登入代碼。

### 3.4 公開觀戰

- 不選隊伍、不輸入密碼即可進入。
- 只接收公開棋盤狀態、角色位置、基地等級、目前通行費、目前過夜費、回合、階段、房市與安全版現場訊息。
- 不接收任何隊伍的現金、諂媚點、背包、增益數量、折扣、收據或未揭曉名次資料。

## 4. 每隊登入代碼

每個活動的每一隊都有兩組由系統自動產生、適合手機輸入的代碼：

- 隊輔代碼，例如 `T-4K7P9`
- 觀眾代碼，例如 `V-8M2RX`

代碼避開 `0/O`、`1/I/L` 等易混淆字元。完整代碼只保存在伺服器的權威狀態與 D1 狀態快照中；任何非主持人狀態投影都必須移除完整憑證集合。驗證時以固定長度雜湊比較，避免直接字串比較。

建立新活動時立即產生所有代碼。舊活動載入時若缺少代碼，Durable Object 必須一次產生並立即同步寫回 Durable Object storage 與 D1，避免休眠後代碼改變。舊的全域 `TEAM_PASSWORD_HASH` 不再作為一般隊輔登入方式，但可在過渡版本中保留為明確受限的管理遷移備援，不得讓它繞過隊伍綁定。

主持人管理區每隊顯示兩張代碼卡，提供複製與重新產生按鈕。重新產生需要確認視窗，並清楚告知對應裝置會被登出。

## 5. 伺服器端狀態投影

新增單一入口 `projectStateForActor(fullState, actor)`，所有 `hello_ok` 與後續 `state` 廣播都必須經過此函式。`broadcast` 不再把同一份 JSON 傳給全部連線，而是逐條讀取 WebSocket attachment 後投影與序列化。

### 5.1 主持人投影

回傳完整狀態。

### 5.2 隊輔與指定隊伍觀眾投影

- 本隊保留完整隊伍狀態。
- 其他隊伍的 `cash`、`pts`、`items`、增益數量、戰鬥剩餘次數、折扣與其他可推算資源的欄位移除或改為 `null`。
- `receipts` 僅保留本隊資料。
- 原始 `log` 不直接傳送，改傳安全公開訊息加本隊私人訊息。
- 隊輔投影額外提供本隊觀眾代碼；指定隊伍觀眾不提供任何代碼。

### 5.3 公開觀戰投影

- 所有隊伍套用公開欄位白名單。
- `receipts` 為空陣列。
- 不傳原始財務日誌。
- 不傳完整登入代碼、未公開名次、總資產或可直接還原現金與點數的衍生欄位。

### 5.4 安全現場訊息

權威狀態新增語意化的 `publicFeed`，由動作類型產生安全訊息，例如「第 3 組抵達稅收格」或「第 2 組完成水大關卡」，不包含實際加扣金額、交易後餘額或諂媚點變化。前端公開戰況只能讀取 `publicFeed`，不得以正規表示式臨時清理原始 `log`。

隊輔與指定隊觀眾的私人金流提示由本隊 `receipts` 產生，不依賴公開訊息。

## 6. 結果揭曉資料

結算前的基地排行榜只依基地等級排序：

1. 未售出且等級較高者在前。
2. 相同等級依固定隊伍編號排列，不使用現金、房產或諂媚點破同分，避免暗示真實名次。
3. 已售出基地排在最後並標示「基地已售出」。

頒獎資料分階段公開：

- 典禮準備：不公開任何名次或總資產。
- 季軍、亞軍、冠軍步驟：只公開已登台隊伍的名次、隊名與總資產；不公開其分項。
- 特別獎步驟：可公開得獎隊伍與獎項名稱，但不顯示能反推完整財產的數值。
- 完整排名步驟：所有連線才收到最終現金、房產、諂媚點與總資產明細。

為避免在前三名揭曉前洩漏排序，非主持人投影不得提早傳送完整排名。伺服器改提供只包含已揭曉名次的 `ceremonyReveal`。只有 `ceremonyStep >= 5` 時，才向所有角色公開完整結算資料。

## 7. 排行榜與收費顯示

隊輔、指定隊觀眾與公開觀戰共用「基地發展榜」，每隊顯示：

- 隊名與角色
- 基地等級及名稱
- 目前經過該基地所需通行費
- 目前停在該基地所需過夜費
- 售出或尚未分配狀態

通行費與過夜費沿用現有 `passFee`、`stayFee` 計算，包含房市倍率與第一回合折扣，因此會隨遊戲狀態即時更新。此區顯示的是目前價格，不是歷史累積收入。

隊輔收據頁永久限制為本隊，不再出現「全場款項」切換。主持人仍可在管理區查看全體收據。

## 8. UI 配置

### 8.1 公開大螢幕

桌面大螢幕採約 70/30 分欄：

- 左側：固定棋盤、3D 移動與重大事件動畫。
- 右上：目前回合、階段、房市、現在操作隊伍。
- 右中：基地發展榜，以基地等級排序並顯示通行／過夜費。
- 右下：安全版即時戰況與五大關解鎖狀態。

移除公開收據、款項異動和財產排行。小尺寸畫面改為單欄，但棋盤仍優先顯示。

### 8.2 隊輔手機與平板

- 維持棋盤在上、操作內容切換的結構。
- 頂部 HUD 只顯示本隊現金、諂媚點、基地與回合狀態。
- 排行榜改為基地發展榜，不顯示其他隊伍財產。
- 收據只顯示本隊。
- 隊伍資訊區新增像素票券樣式的「分享給本隊觀眾」代碼卡與複製按鈕。

### 8.3 觀戰入口

觀戰入口提供兩條清楚路徑：

- 「公開大螢幕」：直接進入，不需密碼。
- 「追蹤我的小隊」：選隊並輸入該隊觀眾代碼。

指定隊伍觀眾採簡化隊輔版面：本隊 HUD、棋盤、基地發展榜、背包狀態與本隊收據，但不渲染任何操作按鈕。

### 8.4 主持人管理區

隊伍管理列保留名稱、連線與資源調整，另加入可收合的登入代碼區。桌面以雙欄代碼卡呈現，手機以直向票券呈現，避免擠壓既有操作。

## 9. 五大關資料與效果

五大關依 `STAGE_IDX` 的棋盤順序固定對應：

| 順序 | 關卡 | 預設效果 | 提示內容 |
| --- | --- | --- | --- |
| 1 | 夜教 | 現金 +500 | 在夜教時反殺警長成功，成功解救所有警察同胞，獲得蔡英文頒獎 500 元。 |
| 2 | 陸大 | 現金 -600 | 吹麵粉吹到關主頭上，關主很開心給你一拳，扣走 600 元。 |
| 3 | 水大 | 現金 +1000 | 在水球大戰中佔據優良地理位置，在水桶底部看到 1000 元。 |
| 4 | RPG | 諂媚點 +10 | 獲得所有物資穿越回現代，並成為校園中的男神／女神，獲得 10 個諂媚點。 |
| 5 | 烤肉 | 現金 +2000 | 因為烤的肉太美味，獲得隔壁奶奶的 2000 元挖角費。 |

`settings.stages` 保存每關名稱、現金變化、諂媚點變化與說明。主持人規則頁可調整每一關的現金與諂媚點，允許正數、零與負數。畫面中的說明必須使用目前設定值動態產生，不能寫死預設金額。

隊伍每次停在已解鎖的關卡格都套用效果：

- 正現金直接加入隊伍現金。
- 負現金使用既有安全付款規則，最多扣到現有現金，並進入銀行庫房，不產生負債或憑空貨幣。
- 正負諂媚點直接調整，但結果不得低於零。
- 每次效果都建立本隊收據。

## 10. 關卡解鎖公告

權威狀態保存遞增的 `stageNotices`，每次首次解鎖一關就新增一筆，包含公告 ID、關卡索引、棋盤位置與當下設定快照。重複點擊已解鎖關卡不建立重複公告。

每台裝置以活動 ID 與公告 ID 在 localStorage 記錄已確認狀態，逐筆顯示未確認公告。因此：

- 在線裝置立即跳出公告。
- 暫時離線或重新整理的裝置，回來後仍會看到尚未確認的公告。
- 公告不自動消失，只有「我知道了」可以關閉。
- 多個關卡快速解鎖時依序排隊，不互相覆蓋。

公告採全螢幕像素關卡卡片，包含關卡名稱、故事、目前實際效果與棋盤用途。夜教公告額外提供「▶ 頒獎奏樂」按鈕，以使用者點擊手勢播放短版頒獎音效；關閉公告與播放音效是兩個獨立按鈕。

## 11. 飛彈自由指定

發動飛彈時先開啟像素雷達選隊視窗，再送出 `targetTeamId`：

- 可選擇任何仍持有基地的其他隊伍，不受排行榜相鄰限制。
- 自己、無效隊伍、已售出或尚未分配基地的隊伍不可鎖定，並顯示原因。
- 後端必須再次驗證目標，不能信任前端選單。
- 成本只在合法目標且攻擊成功時扣除；失敗請求不消耗諂媚點，也不占用本回合飛彈次數。
- 現有飛彈動畫沿用選定隊伍基地座標與隊名。

## 12. 錯誤處理與相容性

- 錯誤隊伍代碼、錯誤觀眾代碼或跨隊代碼一律拒絕登入，不透露代碼是否屬於另一隊。
- 狀態投影缺少本隊或 actor 資料時拒絕連線，不回退到完整狀態。
- 舊活動的收據、關卡解鎖與典禮狀態需正常正規化。
- 若舊活動已進入完整排名步驟，維持公開完整結果；尚未完整揭曉則繼續保密。
- 關卡設定缺失時補上預設值；舊 `unlocked` 陣列保留，不為過去已解鎖關卡補發公告。
- 前端若收到 `null` 私人欄位，不得以 `0` 顯示，統一顯示鎖定符號或省略欄位。

## 13. 測試與驗收

### 13.1 權限與外洩測試

- 主持人投影包含全體完整資料。
- 隊輔與指定隊觀眾只能找到本隊現金、點數與收據。
- 公開觀戰 JSON 中不存在任一隊真實現金、點數、背包與收據。
- 財務日誌文字不出現在公開投影。
- 跨隊使用有效但不屬於所選隊伍的代碼仍登入失敗。
- 重新產生代碼後，舊代碼失效且對應在線連線被關閉。

### 13.2 遊戲規則測試

- 基地發展榜只按等級排序，同級保持固定隊伍順序。
- 通行費與過夜費正確套用房市與第一回合倍率。
- 五關預設值、可調值、重複踩踏與收據都正確。
- 負現金關卡不會讓現金低於零，實付金額正確進銀行。
- 飛彈能指定任一合法對手，非法目標不扣點、不標記已使用。

### 13.3 頒獎測試

- 典禮步驟 0 不洩漏名次。
- 步驟 1–3 只公開已揭曉隊伍的名次與總資產。
- 步驟 4 特別獎不洩漏未公開分項。
- 步驟 5 才公開完整財產表。

### 13.4 UI 與裝置驗收

- 公開大螢幕在目標投影解析度內無需捲動即可看到棋盤、回合、基地榜與快報。
- 隊輔手機和平板保持棋盤優先，操作頁不被新增代碼卡擠壓。
- 公開與指定隊觀戰入口清楚分流。
- 關卡公告在所有角色、重新整理和短暫離線後都必須手動確認，並支援多公告排隊。
- 夜教奏樂按鈕在瀏覽器音效限制下可由點擊正常播放。

## 14. 發佈策略

這次是安全邊界變更，前後端必須同一版本部署，不拆成只更新 UI 的中間版本。完成後提高 build 版本、更新 Service Worker cache，執行語法檢查、完整單元測試、可靠性重現測試與至少一次公開觀戰／隊輔／指定隊觀眾的瀏覽器流程驗收，再推送 `main` 觸發 GitHub 到 Cloudflare Worker 的既有部署流程。

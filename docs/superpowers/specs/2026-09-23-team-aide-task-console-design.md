# 隊輔「人生旅程任務台」介面設計

日期：2026-09-23

## 背景與目標

本設計只改隊輔手機／平板的呈現、導覽及教學，不改主持人權限、四階段順序、扣款、道具、擲骰、BATTLE、事件或勝負規則。現有手機畫面依序堆疊頂欄、隊伍數值、階段列、棋盤與操作面板；棋盤在遊戲頁約佔視窗高度 46%，常使當前可操作按鈕落到首屏外。五個底部頁籤在窄螢幕也過擠。

目標是讓第一次玩的隊輔在每個階段一眼看見「目前狀態、下一步、能按什麼」，同時保留現場像素棋盤與本隊資源。手機以單手操作為先，平板橫向同時展示棋盤與操作。大螢幕觀戰與主控台本次不重排。

## 方案選擇

- 只縮短文案：風險低，但不能解決首屏看不到按鈕，故不採用。
- 傳統 RPG 多層選單：風格契合，卻增加尋找操作的步數，故不採用。
- **情境式任務台（採用）**：當前階段的狀態和主要操作置頂，棋盤平時維持可展開預覽、移動演出時放大；既保留角色扮演感，也減少滾動和誤觸。

## 介面結構

### 手機（窄於 860px）

由上而下：精簡活動／連線頂欄、隊伍資源帶、當前階段任務卡、棋盤預覽、當前操作區；固定底部為四個主要入口：`行動`、`背包`、`收據`、`更多`。`更多`內保留設定、觀眾名單／代碼、遊戲紀錄與玩法重播。收據仍僅顯示本隊可見資訊。活動暫停、離線、操作待確認等警示維持在首屏，但不遮擋主要按鈕。

棋盤預覽始終可見，點擊可手動展開／收合。等待主持人、房市、基地經營、商店及非行動頁時預設為緊湊狀態；輪到本隊且主持人允許擲骰時，棋盤與擲骰區獲得較多空間；擲骰、行走和落格演出期間自動展開／維持演出視角，結束後回到先前手動選擇或階段預設。不可在演出中因伺服器狀態更新而突然收合。預覽不是第二份棋盤 DOM；只改同一實例的佈局和縮放。

底部入口最小觸控區 44×44px，考慮安全區；內容預留底欄高度。小於 420px 時仍顯示四項而非五項。像素字只用於短標籤，說明正文使用可讀字體與尺寸；盡量不用 9px 以下正文。

### 平板（860px 起）

棋盤左側、任務與操作右側；保留同一組四入口與內容邏輯，但入口可位於操作欄上方。棋盤不覆蓋控制鍵。橫放時擲骰、移動視角仍能暫時主導畫面，但不改權威狀態。桌面瀏覽器維持可用，不另外新增第三套流程。

### 資訊優先順序

隊伍資源帶優先顯示本隊現金、房產、諂媚點、當前階段與連線；銀行等次要資訊可收至展開資訊區。本隊數值以現有伺服器投影為準，不推測其他隊伍的金錢或點數。等待狀態用一句清楚的原因，如「等待主持人允許本隊擲骰」，而非只停用按鈕。觀眾批准待辦與新收據可用小徽章提示，但不得把隱私資訊放入公開視角。

## 四階段任務卡與操作

任務卡使用現有 `phase`、`activeTeamId`、`rollDiceCounts`、`pendingBattle`、`pendingCard` 等狀態，只衍生呈現，不持有另一份遊戲規則。它顯示一個主要狀態／動作與至多一行提示：

1. 房市：目前倍率與影響，等待主持人切階段。
2. 基地經營：基地等級，升級、賣出或買回（沿用現有可用性、費用與確認）。
3. 商店：增益與實體物品分組，先看作用／價格，既有二次確認後才送出購買。
4. 移動：明確顯示本隊是否被允許、骰子顆數與主要滑動擲骰區；未允許時只顯示等待，不做假可用按鈕。

待處理 BATTLE、機會／命運卡、監獄、五大關公告、修繕與金流通知的優先度高於一般任務提示。保留現有選擇視窗及演出順序，不以教學卡覆蓋它們。進階特殊操作沿用現有展開模式，不變更成本／次數。

## 互動式教學

沿用已存在的四階段教學與本機已讀記錄，不另建伺服器流程。第一次進入以可跳過的短導覽指出真實畫面上的資源、棋盤預覽、當前任務與底部入口；每階段只出一個短提示，使用者可按「我知道了」。`更多 → 玩法`可重播。提示須有文字替代，不單靠顏色、動畫或音效。只在安全的待機時機顯示；擲骰、移動、落格、結算及待主持人裁決時不彈出。重播教學不重置已進行的遊戲狀態。

## 狀態、弱網與可近用性

頁籤、棋盤展開狀態與教學目前步驟都是純客戶端 UI 狀態；切頁不離開遊戲或重新建立 WebSocket。重新同步後仍使用伺服器權威狀態渲染，沒有樂觀扣款。`send()` 的 action ID、待確認訊息和補送機制保持不變，送出後主按鈕明確呈現「等待確認」，避免弱網連點。離線時顯示最後同步狀態，不假裝操作已成功。

切換頁籤、重繪任務卡或展開棋盤不可打斷擲骰手勢、動畫計時、BATTLE 選擇與待確認操作。鍵盤可操作所有新按鈕；展開鈕帶 `aria-expanded`，教學與狀態更新有適度語意；支援 `prefers-reduced-motion`。在低階手機避免額外大圖或持續性動畫，沿用現有像素素材與 CSS。

## 實作邊界

主要觸及 `public/app.js`（隊輔頁籤、任務卡、棋盤展開的本地 UI 狀態、教學觸點）與 `public/styles.css`（手機和平板佈局、底欄、可讀性、動效降級）；必要時更新既有前端測試。不得修改伺服器遊戲結算、資料格式、D1 schema 或公開觀戰／主控台流程。若實作發現原有 `renderGame()` 會在同步更新時打斷進行中的手勢，僅做保護 UI 互動所需的局部調整。

## 驗收

- 360px、390px 手機及 768px、1024px 平板（直、橫）上，當前可做的操作不被棋盤或底欄遮住；無水平溢出。
- 四階段、等待主持人、允許擲骰、待 BATTLE、待卡片裁決、暫停、弱網和結算各狀態，文案與可用按鈕正確。
- 切換背包／收據／更多後回行動，棋盤和 WebSocket 不重建；移動演出不抽動、不被教學插入。
- 購買、升級、擲骰、Battle 等仍呼叫原 action，費用與結果和改版前相同；收據、隱私與觀眾名單維持正確。
- 既有自動化測試、語法檢查與 Wrangler dry-run 通過；手動以手機與平板視窗檢查互動。

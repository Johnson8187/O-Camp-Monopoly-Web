# 像素人生旅途祭典視覺體驗設計

日期：2026-08-22  
狀態：已定案，待實作

## 1. 目標

將現有宿營「人生大富翁」包裝成一場「像素人生旅途祭典」，以人生道路、城市發展、房產累積與團隊選擇為敘事核心，強化首頁儀式感、大螢幕演出、隊輔裝置回饋與結算氣氛，同時維持目前遊戲規則、狀態流程、權限、排名與數值計算不變。

主要使用情境：

- 現場參加者與工作人員使用首頁進入活動。
- 大螢幕顯示全場即時戰況。
- 每隊隊輔以手機或平板操作，並將畫面展示給小隊成員。
- 主持人使用控制台管理既有流程。
- 大螢幕連接音響；隊輔裝置進入遊戲後預設開啟短音效。

## 2. 最高限制：不得改變遊戲規則

所有新增內容只能位於視覺、音效、震動與前端演出層。

允許：

- 讀取既有活動狀態、回合、隊伍、事件、收據與操作結果。
- 依已確認的狀態播放動畫、音效、震動與視覺餘波。
- 在不阻塞操作的前提下排隊或略過視覺演出。
- 依裝置效能與使用者偏好簡化動畫。

禁止：

- 新增獎勵、懲罰、貨幣、隨機事件或隱藏條件。
- 改變骰點、回合、房市、Battle、排名、特殊操作或收付款規則。
- 由動畫完成與否決定操作是否成功。
- 在伺服器尚未確認前，把操作呈現為成功。
- 因跳過動畫而跳過遊戲階段或規則處理。

單向資料流必須維持：

```text
既有伺服器狀態／確認結果
          ↓
    視覺事件轉換器
          ↓
動畫、短音效、震動、視覺餘波
```

視覺系統不得反向寫入規則狀態。

## 3. 美術方向

整體主題為「像素人生旅途祭典」。像素風格是固定限制，不採用一般 SaaS 卡片、玻璃擬態或寫實 3D 美術。世界觀不得偏移成奇幻 RPG；冒險感只能用來表現人生旅程與團隊挑戰。

### 3.1 視覺語言

- 延續現有米白、墨黑、金黃、紅色與隊伍色。
- 使用硬邊、有限色盤、像素陰影與清晰輪廓。
- 場景元素包含人生道路、啟程廣場、發展中的像素城市、里程碑塔、祭典布旗、路燈、公告報紙與隊伍旗幟。
- 爆炸、煙霧、火焰、金幣、能量光點與天氣粒子皆以像素方塊構成。
- 資訊框採像素旅途手冊、人生記事、報紙或城鎮看板語彙；背包可以保留 RPG 式操作感，但內容語意是旅途資源。
- 不用大量等權卡片填滿畫面；先建立完整場景，再將功能自然放入場景。

### 3.2 人生主題比例與敘事

視覺敘事比例固定為：

- 50% 人生旅程、道路、選擇與里程碑。
- 30% 城市、房產、基地與資源發展。
- 20% 宿營祭典與隊伍競賽。

核心句為：「每一次選擇，都讓人生走向不同方向。」各隊不是征服王國的奇幻冒險者，而是走在不同人生道路、共同打造城市與累積經驗的行動隊伍。

既有內容的視覺轉譯：

- 棋盤代表人生道路與城市街區。
- 基地依既有等級從小屋、公寓、商業建築發展為城市地標；只改外觀，不改價值與規則。
- 房市以城市新聞、公告報紙與行情跑馬燈呈現。
- Battle 包裝為基地攻防或商業競爭，不呈現英雄打怪。
- 災難代表人生中的環境風險與意外，結果仍完全遵照既有規則。
- 諂媚點數可用社交網絡、握手或影響力光點輔助呈現，但名稱一律保留「諂媚點數」。
- 排名代表各隊目前的資源與城市發展成果，不使用征服、稱王或佔領王國的語言。

### 3.3 動態原則

- 像素角色、粒子與介面可使用階梯式節奏和定格感。
- 鏡頭追蹤、縮放、位移與大場景轉場保持平順，像素風不等於低幀率。
- 日常環境動畫保持低強度；重大演出開始時自動退場，避免搶戲。
- 所有非必要動畫支援 `prefers-reduced-motion`。

## 4. 首頁：人生啟程廣場

首頁的主要表面類型為 Decide / Learn，次要表面為即時活動 Monitor。它不是宣傳網站，而是現場工作人員與參加者的活動開幕大廳。

### 4.1 構圖

```text
┌─────────────────────────────────────┐
│ 火炬       人生大富翁祭典       火炬 │
│          目前活動狀態／集結隊數       │
├───────────────────┬─────────────────┤
│                   │  活動情報卷軸     │
│ 人生道路與像素城市 │  活動名稱         │
│   各隊旗幟集結     │  目前狀態         │
│                   │  已連線隊伍       │
├───────────────────┴─────────────────┤
│ 進入即時廣場 │ 隊伍報到 │ 祭典總管    │
└─────────────────────────────────────┘
```

三個入口沿用既有路由與權限：

- 進入即時廣場：觀戰入口。
- 隊伍報到：隊輔入口。
- 祭典總管：主持人控制台。

### 4.2 狀態呈現

- 無活動：清晨準備狀態，啟程廣場安靜、道路尚未點亮。
- 隊伍集結：依已連線隊伍顯示旗幟，路燈、城市窗戶與廣場逐漸亮起。
- 活動進行中：道路向遠方延伸，顯示目前回合與立即觀戰入口。
- 活動結束：所有隊伍共同建立的城市亮起，廣場進入里程碑慶典狀態。

上述內容只讀取既有狀態，不增加新的準備或開始條件。

### 4.3 首次短開場

首次進入首頁時播放約 5 至 7 秒：

1. 黑幕、營火與微弱環境聲。
2. 一條人生道路從黑暗中逐格亮起。
3. 活動標題像旅途手冊展開，城市輪廓沿道路升起。
4. 已報到隊伍從不同方向抵達廣場，旗幟依序落下。
5. 顯示「每一次選擇，都讓人生走向不同方向」，道路延伸並出現操作入口。

要求：

- 開場可立即跳過。
- 活動資料在背景同時載入，不等待動畫結束。
- 使用裝置本機狀態記錄已看過，正常情況不重播。
- 開場失敗或資源缺失時，立即顯示可操作首頁。
- 不因開場阻擋觀戰、隊輔或主持人入口。

## 5. 三段式重大事件演出

每個重大事件使用「預兆 → 爆發 → 餘波」結構。

### 5.1 預兆

約 0.8 至 1.2 秒，建立注意力並暫時降低環境動畫：

- 地震：燈光變暗、石屑落下、低頻隆隆聲。
- 飛彈：像素瞄準框、掃描與短警報。
- 颱風：天空變暗、旗幟受風、風聲漸強。
- 野火：畫面邊緣轉橘紅並出現火星。
- Battle：雙方旗幟進場，中央顯示像素 `VS`。

### 5.2 爆發

約 2 至 3 秒：

- 地震：像素地面裂開，受影響格子產生高低錯位。
- 飛彈：遠方高速落下，命中後形成像素衝擊波。
- 颱風：大型旋轉像素雲掃過棋盤與受影響旗幟。
- 野火：火焰從棋盤邊緣依序蔓延。
- Battle：雙方基地、旗幟與角色剪影交鋒後顯示既有結果。

### 5.3 餘波

主動畫結束後保留較低調的裂痕、彈坑、風雨或餘火，並顯示受影響隊伍及既有規則得出的結果。餘波在下一個高優先級演出或適合的操作節點淡出，不影響後端狀態。

## 6. 裝置分工

### 6.1 大螢幕：全場史詩演出

- 播放完整首頁開場、重大事件、排名換位、回合與頒獎演出。
- 承擔背景環境聲、完整事件聲與低頻衝擊。
- 動畫期間仍顯示事件名稱、發動隊伍、受影響對象與結果。
- 不需要主持人額外手動播放。

### 6.2 隊輔手機／平板：本隊人生視角

隊輔裝置同時是小隊成員觀看的小型舞台，不只是一個控制器。

- 自己隊伍的操作與受影響事件播放約 1.5 至 2.5 秒的中型像素動畫。
- 動畫可以全畫面，但結果出現後可立即關閉，不延誤操作。
- 手機降低粒子數；平板使用較完整構圖。
- 顯示本隊在事件中的角色、結果與資源變化。

主要演出：

- 擲骰：甩出骰子、落地顯示總點數、鏡頭跟隨本隊棋子。
- 購買：人生補給箱或行李箱開啟，道具卡升起後飛入背包。
- 防災卡：像素護盾擋下事件，卡片碎成光點並標示消耗。
- 發動攻擊：本隊站在施放／發射場景中啟動事件。
- 遭受攻擊：短警報、基地受擊與既有修繕結果。
- Battle：依攻守身分從不同方向進場。
- 收付款：金幣飛入或飛出錢袋，接著蓋上電子收據印章。
- 排名上升：隊旗向上換位並顯示 `RANK UP`。
- 輪到本隊：隊旗展開、邊框切換為隊伍色並震動提醒。

### 6.3 主持人：穩定操作

- 重大事件只顯示角落播放狀態與已確認結果。
- 可靜音大螢幕、跳過目前視覺或清除卡住的演出。
- 跳過視覺不得跳過任何規則、階段或後端處理。
- 動畫不清除主持人尚未送出的輸入。

## 7. 擲骰跨裝置演出

隊輔向上甩動後，手機端骰子飛出畫面；伺服器確認骰點後，大螢幕從該隊旗幟方向讓骰子飛入、滾動並落地。大螢幕與手機都以伺服器結果為唯一真相，不由手勢速度或動畫決定點數。

若大螢幕未連線或動畫排隊，手機仍立即顯示已確認結果，遊戲可以繼續。

## 8. 音效與震動

### 8.1 大螢幕

第一次進入觀戰時顯示像素化的「點燃祭典之火」音訊解鎖操作。聲音分為：

- 低音量環境聲。
- 操作聲。
- 重大事件聲。
- 開局、排名、回合與頒獎儀式聲。

同一時間只保留一個主要事件聲。

### 8.2 隊輔裝置

- 進入遊戲後預設開啟短音效。
- 使用加入隊伍的點擊解鎖瀏覽器音訊。
- 自動恢復連線時若遭瀏覽器阻擋，顯示一次「點擊喚醒隊伍音效」。
- 只播放約 0.2 至 2 秒的短音效，不播放背景音樂與強低頻。
- 骰子、金幣、補給箱、護盾、攻擊、受擊與排名各有可辨識聲音。
- 多個事件同時出現時只播放優先級最高者。
- 保留隨時可用的靜音按鈕，並尊重裝置音量設定。
- 支援震動但不依賴震動傳達唯一資訊。

## 9. 視覺演出佇列

前端建立獨立演出佇列，避免事件互相覆蓋：

- 收據與數值在伺服器確認後立即更新，不等待動畫。
- 小型金流事件可合併或略過。
- 重大事件依優先級與時間依序播放。
- 新回合或更高優先級事件可以結束低強度餘波。
- 重連時不重播已完成的歷史事件。
- 動畫錯誤、逾時或資源缺失時直接顯示結果。

演出項目至少包含唯一事件識別、類型、優先級、目標角色、開始時間、最大播放時間與降級呈現內容。佇列狀態只存在前端，不寫入規則資料。

## 10. 日常環境與階段包裝

- 火炬低強度跳動、旗幟緩慢飄動、棋盤偶爾掠過雲影。
- 房市階段以城鎮公告板更換既有行情。
- 商店階段點亮攤販燈籠並播放短金幣聲。
- 擲骰階段讓中央廣場與目前隊伍旗幟亮起。
- 隊伍領先或排名交換只改變旗幟位置與短演出，不增加效果或獎勵。
- 結算依既有排名結果依序登上人生里程碑舞台；所有隊伍的城市共同亮起，前三名升旗，冠軍旗幟最後升至中央里程碑塔。

## 11. 效能、可用性與退化

- 大螢幕使用完整場景與粒子；手機和平板依尺寸和效能降低粒子量。
- 偵測持續掉幀時先降低背景粒子，不降低操作回應。
- 重大動畫設最大播放時間，逾時直接進入結果狀態。
- 音效載入失敗不阻擋操作。
- `prefers-reduced-motion` 下改用短轉場、靜態結果卡與必要狀態提示。
- 所有音效與色彩變化均有文字結果，不以聲音或顏色作為唯一訊息。
- 手機操作目標至少 44px，重要按鈕不被演出永久遮擋。

## 12. 實作邊界

建議將視覺功能拆為獨立單元：

- Life Journey Home：人生啟程廣場、入口與首次開場。
- Presentation Mapper：將既有狀態差異轉為視覺事件。
- Presentation Queue：管理優先級、合併、逾時與跳過。
- Pixel Scene Renderer：大螢幕與隊輔端不同強度的場景。
- Sound Director：音訊解鎖、音量、優先級與靜音。
- Performance Controller：裝置分級、掉幀監測與減少動態效果。

上述單元只能消費既有遊戲狀態或已確認事件，不直接呼叫改變遊戲規則的 action。

## 13. 驗證標準

功能與規則：

- 同一套測試資料在加入視覺系統前後產生相同骰點、數值、收據、排名與階段結果。
- 動畫失敗、跳過、靜音或重整不改變遊戲狀態。
- 只有伺服器確認成功的操作會播放成功演出。
- 斷線重連不重播已完成事件。

裝置與視覺：

- 手機直向隊輔操作與觀看。
- 平板橫向隊輔操作與觀看。
- 1920×1080 大螢幕完整演出。
- 主持人連續操作時不遺失尚未送出的輸入。
- 音效開啟、靜音、瀏覽器阻擋與載入失敗情境。
- 一般、低效能與減少動態效果模式。
- 多事件連續到達時，佇列不重疊、不永久遮蔽結果。

## 14. 建議實作順序

1. 建立視覺事件轉換器、佇列與規則隔離測試。
2. 重做首頁人生啟程廣場與首次短開場。
3. 建立音效管理與瀏覽器解鎖流程。
4. 完成隊輔端擲骰、購買、防災、金流與輪到本隊演出。
5. 完成大螢幕三段式災難與 Battle 演出。
6. 加入環境階段包裝、排名換位與結算升旗。
7. 完成效能分級、減少動態效果與跨裝置驗證。

# 代碼直達、具名觀眾管理與大螢幕自適應設計

日期：2026-08-25

## 目標

這次調整不改動人生大富翁的遊戲規則，只改善登入、保密管理、首頁資訊層級與公開大螢幕排版：

1. 隊輔與私人觀眾不再先選隊伍，後端直接由專屬代碼判斷所屬隊伍。
2. 成功登入後記住裝置，下次有同一場活動時直接回到該隊；代碼或觀眾資格失效才重新登入。
3. 私人觀眾必須署名並經隊輔批准，隊輔可查看、批准、拒絕及移除人員。
4. 隊輔可以一鍵隨機重設本隊觀眾代碼；重設後舊代碼與既有觀眾資格全部失效。
5. 首頁只保留祭典主視覺上的四個入口，移除下方重複的活動入口卡片。
6. 公開大螢幕在常見 16:9、4:3 與矮螢幕比例中維持單畫面戰況，不發生棋盤或側欄溢出。

## 不在範圍內

- 不修改移動、房產、點數、特殊操作、關卡與頒獎規則。
- 不建立帳號、Email、手機驗證或永久跨活動會員系統。
- 不嘗試以瀏覽器指紋封鎖真人；保密邊界由批准名單、可撤銷工作階段與觀眾代碼重設維持。
- 公開免密碼的大螢幕觀戰仍然保留，並持續只取得公開投影資料。

## 方案選擇

採用「共用入場代碼＋具名申請＋獨立觀眾工作階段」。相較於只記姓名，此方案能精確撤銷某位觀眾；相較於每人一組邀請碼，現場隊輔不必逐人發碼，操作成本較低。

## 資料模型

### 隊伍存取代碼

每隊維持：

- `teamCode`：隊輔登入代碼，格式 `T-XXXXX`。
- `viewerCode`：私人觀眾申請代碼，格式 `V-XXXXX`。

新建及舊資料遷移時，伺服器必須確保同一活動內同類代碼不重複。代碼比較不分大小寫。前端不再傳送由使用者選擇的隊伍作為授權依據；伺服器搜尋代碼後決定 `teamId`。

### 觀眾名單

遊戲狀態新增每隊觀眾記錄，單筆包含：

- `id`：不可猜測的觀眾識別碼。
- `teamId`：所屬隊伍。
- `name`：1–20 字的顯示名稱，移除前後空白並轉義顯示。
- `status`：`pending`、`approved`、`rejected` 或 `removed`。
- `sessionTokenHash`：批准時建立的獨立工作階段雜湊；完整 token 只回傳給該裝置一次。
- `requestedAt`、`approvedAt`、`lastSeenAt`、`removedAt`：管理與排序所需時間。

同一隊的有效 `pending`／`approved` 名稱採不分大小寫唯一。已拒絕或移除的名稱可再次申請，但仍必須重新批准。每隊最多保留最近 60 筆記錄，清除時優先移除最舊的拒絕／已移除資料，不刪除待審核或已批准記錄。

## 登入與記憶流程

### 隊輔

1. `/team` 取得目前唯一活動。
2. 若本機存有該活動的隊輔代碼，直接建立 WebSocket 並送出 `role: team` 與代碼。
3. 伺服器查找代碼並決定隊伍，回傳投影狀態與 `teamId`。
4. 成功後以 `localStorage` 記住活動 ID、角色與代碼；再次開啟時自動進入。
5. 若主持人重設隊輔代碼，既有連線立即收到資格失效訊息並斷線，本機清除舊資料，回到單一代碼輸入頁。

### 私人觀眾第一次進入

1. `/watch` 顯示觀眾代碼與署名欄，不顯示隊伍清單。
2. 伺服器由觀眾代碼決定隊伍，建立或更新 `pending` 申請。
3. 申請裝置進入等待室，只收到活動名稱、所屬隊名與申請狀態，不取得私人遊戲狀態。
4. 隊輔在設定頁批准後，伺服器建立獨立 session token，主動通知等待中的裝置。
5. 裝置保存 viewer ID 與 session token，重新以已批准觀眾身分連線，才取得該隊的私人狀態投影。

### 私人觀眾再次進入

本機若有同一活動的 viewer ID 與 session token，直接驗證並回到該隊。代碼本身不必重送。若資格被移除、觀眾代碼被重設或活動已更換，伺服器拒絕舊 session，前端清除記憶並回到申請頁。

### 公開觀戰

首頁的「進入即時廣場」維持免密碼，WebSocket attachment 為公開 viewer，伺服器只回傳公開投影；此流程不要求署名，也不出現在任何隊伍的人員名單。

## 隊輔觀眾管理

隊輔頂部頁籤新增「設定」。設定頁包含：

1. 本隊觀眾代碼：醒目顯示、複製按鈕與「一鍵隨機重設」。
2. 待批准：顯示署名與申請時間，提供「允許」及「拒絕」。
3. 已批准：顯示在線／離線與最後活動時間，提供「移除」。
4. 已拒絕／已移除：縮成最近紀錄，不顯示敏感 token，也不提供直接恢復；對方必須重新申請。

重設觀眾代碼必須二次確認。成功後：

- 產生新的隨機 `V-XXXXX`。
- 所有待批准申請改為 `rejected`。
- 所有已批准觀眾改為 `removed`，清除工作階段雜湊。
- 立即通知並斷開本隊全部私人觀眾。
- 不登出隊輔、不改變隊輔代碼，也不影響公開大螢幕。

隊輔不得修改隊輔代碼；隊輔代碼仍只由主持人管理。主持人控制台保留兩種代碼的查看及重設權限。

## WebSocket 與權限邊界

`hello` 支援四種驗證：

- 公開 viewer：無代碼、無隊伍，直接建立公開連線。
- team code：送出隊輔代碼，伺服器解析隊伍。
- viewer request：送出觀眾代碼與署名，只能建立／查看自己的待審核狀態。
- approved viewer session：送出 viewer ID 與 session token，伺服器驗證雜湊與 `approved` 狀態。

WebSocket attachment 對隊輔保存 `role/teamId`；私人觀眾保存 `role/teamId/viewerId`。`projectStateForActor` 繼續作為所有遊戲狀態的唯一輸出入口。等待批准者不進入遊戲廣播名單，也不呼叫私人狀態投影。

新增隊輔可執行且只能作用於本隊的操作：

- `approveViewer`
- `rejectViewer`
- `removeViewer`
- `regenerateOwnViewerCode`

主持人沿用既有 `regenerateAccessCode`。所有操作在伺服器核對 actor 的 `teamId`，不能只依賴前端隱藏按鈕。

## 首頁資訊層級

首頁祭典主圖保留四個入口：

1. 進入即時廣場（公開大螢幕）
2. 隊伍報到（隊輔）
3. 追蹤我的小隊（私人觀眾）
4. 祭典總管（主持人）

移除主圖下方「即時人生廣場」活動清單與其中的重複入口。活動是否開放、隊伍集結數及目前階段整合回主圖既有狀態卷軸；重新整理改成狀態卷軸內的小型圖示按鈕。首頁不再因活動清單增加額外高度。

## 公開大螢幕排版

公開觀戰以「固定一個 viewport、局部內容自適應」為原則，不以整頁捲動補救。

### 16:9 與寬螢幕

- 棋盤區約占可用寬度 64–70%，右側戰況欄占 30–36%。
- 右欄由上到下為階段／現在操作、基地排行榜、即時事件與五大關狀態。
- 排行榜依實際隊伍數使用一或兩欄；卡片密度由可用高度決定。

### 4:3 或中等寬度投影

- 棋盤與右欄比例約 58／42，右欄縮為單欄資訊卡。
- 隱藏裝飾性副標與重複圖例，保留隊名、基地級數、通行費、過夜費、階段與重大事件。
- 字體以容器可用尺寸使用 `clamp()`，避免單純按照螢幕寬度放大。

### 矮螢幕與特殊瀏覽器工具列

- 使用 `100dvh` 與實際 topbar／phase track 高度計算內容區。
- 棋盤縮放同時受寬度與高度限制，右欄卡片使用高度密度等級，不讓內容把整頁撐高。
- 排行榜或事件過多時只在各自卡片內捲動；頁面本身保持固定。

### 非投影的窄螢幕

公開觀戰若小於平板寬度則退化為正常可捲動的上下排列，不強制把棋盤與所有戰況壓在單一手機畫面。私人觀眾沿用手機／平板操作版，不套用大螢幕固定 viewport 規則。

## 錯誤處理與濫用限制

- 錯誤代碼只回覆「代碼無效或已更新」，不洩漏存在的隊伍。
- 觀眾署名驗證失敗在送出前及後端各檢查一次。
- 同一 WebSocket／短時間來源重複申請使用輕量冷卻，避免隊輔名單被大量洗版。
- 待批准連線只接收自己的申請結果；斷線後可用代碼與相同署名重新提出或恢復待審核申請。
- 批准、拒絕、移除與重設都寫入稽核 log，但公開 feed 不顯示觀眾姓名。
- Durable Object 重啟後，以儲存狀態中的觀眾記錄和 token hash 恢復資格；在線狀態則由現有 WebSocket 動態計算。

## 測試與驗收

### 後端

- 正確隊輔代碼可解析隊伍，錯誤或跨角色代碼不能登入。
- 代碼生成在同一活動內唯一，舊活動可正常遷移。
- 待批准觀眾無法取得任何私人狀態。
- 隊輔只能批准、拒絕及移除本隊觀眾。
- 移除單一觀眾只撤銷該 session；重設觀眾代碼撤銷全隊所有私人觀眾。
- 公開觀戰仍免密碼且不洩漏財務、點數、收據、背包、代碼及觀眾名單。

### 前端

- `/team` 與 `/watch` 都沒有選隊步驟。
- 已記住且仍有效的資格會自動進入；失效時清除並回到正確入口。
- 等待室、批准、拒絕、移除與代碼重設的畫面狀態完整。
- 隊輔設定頁可複製代碼並管理名單，不暴露 session token。
- 首頁只存在一組四入口，沒有下方重複活動按鈕。

### 視覺與響應式

- 以至少 1920×1080、1366×768、1280×1024、1024×768 驗證公開大螢幕。
- 驗收各尺寸頁面本身無水平或垂直溢出，棋盤完整可見，右欄的重要資訊不重疊。
- 以手機寬度驗證隊輔設定與私人觀眾等待室，按鈕尺寸與名單操作適合觸控。

## 上線與相容性

現有活動在首次載入新 Worker 時補上空的觀眾名單與必要欄位。既有隊輔若本機仍保存有效隊輔代碼，可直接由新流程解析隊伍；既有私人觀眾因尚無具名批准憑證，必須輸入署名並經隊輔批准一次。部署仍由推送 GitHub `main` 觸發 Cloudflare Worker 建置。
